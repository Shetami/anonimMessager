# Модель угроз и устройство защиты

## От чего защищает

| Угроза | Защита |
|---|---|
| Перехват трафика, взлом TLS, подменённый сертификат | E2E-шифрование Signal Protocol; TLS 1.3 + SPKI-пиннинг; паддинг до фиксированных размеров (1/4/16/64 КБ) |
| Взломанный или изъятый сервер | Сервер видит только ID ящика получателя и зашифрованные конверты. Отправитель, текст, время отправки и размер сообщения ему неизвестны. Ключи хранятся только на устройствах |
| Сервер подменяет ключи (MITM) | ID контакта = SHA-256(identity key). Клиент отвергает любой ключ, хэш которого не совпадает с ID: и при добавлении контакта, и в `isTrustedIdentity`. Окна доверия при первом контакте (TOFU) нет |
| Компрометация ключей в будущем | Forward secrecy и post-compromise security (Double Ratchet), постквантовый PQXDH (Kyber) |
| Изъятое заблокированное устройство | Файлы под `NSFileProtectionComplete`; данные зашифрованы ключом, производным от кода + секрета Secure Enclave |
| Копия файлов приложения / бэкап | Секрет устройства живёт в Secure Enclave и не экспортируется. Без этого конкретного телефона перебор кода невозможен. Файлы исключены из бэкапов |
| Принуждение разблокировать | Ложный код открывает второй профиль. Файл сейфа имеет фиксированный размер и не содержит заголовков, оба слота всегда заполнены, обе базы созданы при установке |
| Беглый осмотр телефона | Приложение выглядит как калькулятор. В переключателе приложений виден калькулятор. После сворачивания автоблокировка, история вычислений не сохраняется |
| Скриншоты и запись экрана | Содержимое мессенджера рендерится в защищённом слое; при записи или трансляции экран закрывается калькулятором |
| Клавиатурные шпионы | Сторонние клавиатуры запрещены; автокоррекция в чате отключена |
| Буфер обмена | Копирование только локально (без Universal Clipboard), очистка через 60 секунд |
| «Уничтожить всё» | Crypto-erase: удаление секрета Secure Enclave и перезапись файла сейфа делают все данные невосстановимыми мгновенно |

## Устройство

```
код ──PBKDF2(400k)──┐
                    ├─HKDF─► KEK ──AES-GCM──► master key слота (2 слота, 152 байта, без заголовка)
секрет Secure Enclave┘                              │
                                                    ├─► ключ БД (ChaCha20-Poly1305 на каждую запись)
                                                    └─► ключ индексов (HMAC от имён, ключей и групп)
```

- **Профиль** = слот сейфа + своя БД + своя Signal-идентичность + свой ящик на сервере. Профили ничего не знают друг о друге. Только основной профиль хранит (в своей зашифрованной БД) master key второго слота, чтобы назначить ему ложный код.
- **Отправка:** `Signal(payload)` → `{sender, ciphertext}` → паддинг → ECDH(эфемерный X25519, sealing key получателя) + ChaCha20-Poly1305 → `PUT /v1/messages/{id}` без аутентификации. Sealing key подписан identity-ключом получателя, подпись проверяется.
- **Получение:** запрос подписан отдельным Ed25519-ключом ящика (временная метка, nonce, хэш тела, защита от replay). Этот ключ доказывает серверу только владение ящиком.

## Ограничения (важно)

1. **IP-адрес виден серверу** и провайдеру. Сервер его не пишет, но может быть принуждён начать. Для сокрытия используйте VPN/Tor. Поддержки Tor в приложении пока нет.
2. **Метаданные времени.** Сервер видит, когда в ящик X приходят конверты и когда X их забирает. Корреляция по времени между ящиками возможна.
3. **Нет push-уведомлений.** Сообщения приходят только пока мессенджер открыт: push раскрыл бы связь с Apple и сервером. Если понадобится, можно добавить push без содержимого.
4. **Ложный профиль правдоподобен настолько, насколько вы его наполнили.** Объём файла БД основного профиля растёт с перепиской. Пустой ложный профиль рядом с большим файлом выглядит подозрительно. Заведите в ложном профиле обычные чаты.
5. **«Уничтожить всё» из ложного профиля стирает и основной.** Это сделано намеренно, как кнопка паники.
6. **Протокол запечатанного конверта и сейфа — собственная разработка** поверх стандартных примитивов CryptoKit. libsignal проверен годами, а эти слои аудита не проходили. До реального использования в опасных условиях нужен независимый аудит.
7. **Защита от скриншотов** опирается на внутреннее устройство `UITextField`, которое Apple может изменить. Если оно перестанет работать, содержимое просто будет видно на скриншоте.
8. **Взломанное (jailbreak) или скомпрометированное устройство** снимает почти все гарантии: вредоносный код в памяти видит открытые данные. Приложение предупреждает о признаках jailbreak, но не может гарантированно его обнаружить.
9. **PBKDF2, а не Argon2:** CryptoKit не предоставляет memory-hard KDF. Основная защита от перебора — секрет Secure Enclave. Используйте коды длиннее 4 символов; выражение вида `7391×2843` работает лучше простого PIN.
10. **Регистрация без защиты от спама.** Сервер ограничивает очередь ящика (5000 конвертов) и размер конверта (256 КБ), но не ограничивает количество регистраций. Перед публичным запуском добавьте proof-of-work или rate limit на прокси.
11. **Одно устройство на профиль.** Синхронизации между устройствами нет, бэкапов тоже, это сделано намеренно. Потеря телефона означает потерю переписки.
